Can Tabular Foundation Models beat a production-style PD scorecard?

A fair, same-fold, same-data comparison of three TFMs against a WoE-logistic-regression champion on the German Credit dataset.

TabPFN v2 TabICL TabDPT WoE-Logistic (champion) XGBoost LightGBM

TL;DR

Tabular Foundation Models (TFMs) show a +1.0 to +1.6 pp AUC lift over an expert-built WoE-logistic champion scorecard, but this advantage is not statistically significant (DeLong p ≈ 0.10, Bonferroni-corrected ≈ 0.58). Even after hyperparameter tuning the classical models (XGBoost, LightGBM), the TFM edge persists but remains within the noise band of a 1,000-observation dataset.

Bottom line: TFMs are competitive with production-style scorecards on small credit-risk datasets. They don't decisively win, but the fact that zero-shot / minimal-config models match a hand-tuned WoE pipeline is remarkable for practitioners.

Why this comparison is fair (and others aren't)

The problem with published TFM benchmarks

Most TFM papers (TabPFN, TabICL, TabDPT) evaluate on raw UCI datasets with default preprocessing. But credit-risk practitioners don't build models that way. A production-style PD scorecard involves:

  • Weight-of-Evidence (WoE) binning with monotonicity constraints
  • Information Value (IV) based variable selection
  • Stepwise logistic regression with VIF/correlation checks
  • Expert overrides for business-logic and regulatory constraints

Comparing a TFM against a "default logistic regression on raw features" isn't comparing against the model a bank would actually deploy. That comparison flatters TFMs — it's beating a straw man.

What we did differently

Key design choice: We built a full production-style PD scorecard first (using the pd-autopilot pipeline), then ran every model — TFMs included — on the same raw data, same folds, same evaluation protocol.
  • Same data: All 7 models are evaluated on the same 1,000 observations and fold splits. TFMs and raw-feature classical models see the 20 original features; the champion uses its fixed 8-variable WoE representation.
  • Same folds: All models share the exact 10-fold CV split (seed=42, stratified). Per-fold AUC differences are paired, not independent.
  • Same evaluation: AUC / Gini / KS are reported as fold mean ± standard deviation; concatenated out-of-fold predictions are used for ROC plots and paired DeLong tests.
  • Champion gets its own features: The WoE-logistic model uses its own WoE-transformed features (as it would in a scorecard pipeline), while TFMs and raw-feature classicals get the original features. This is fair — each model gets its natural input.

Why 10-fold cross-validation?

With only 1,000 observations, a single train/test split is dominated by sampling noise. 10-fold stratified CV gives every observation exactly one out-of-fold prediction, enabling:

  • Paired statistical tests (DeLong, Wilcoxon) — testing whether model A beats model B on the same borrowers, not on different random subsets.
  • Variance estimates — the ± in our AUC numbers comes from fold-level variation, showing how unstable each model is.
  • No cherry-picking — every observation is scored exactly once, so concatenated out-of-fold predictions provide an honest out-of-sample basis for ROC plots and paired tests.

Why results differ from the original report

Not directly comparable. The original pd-autopilot report shows dev AUC = 0.811 and CV AUC = 0.807 for the WoE-logistic champion. Our benchmark shows 0.784. This is expected — the report's CV ran on already-cleaned data (loans_clean.csv) with preprocessing fitted on the full dataset, while our benchmark runs on raw data with preprocessing strictly inside each fold. The lower number is the more honest one.

Technical details

Dataset

  • German Credit (Statlog) — 1,000 observations, 20 features
  • Target: Creditability (1 = default, 30% prevalence)
  • Mix of ordinal, nominal, and continuous predictors
  • Raw features used — no pre-cleaning, no imputation outside the fold

Evaluation protocol

  • 10-fold stratified CV, seed=42
  • All models share the exact same folds
  • Out-of-fold predictions concatenated (7,000 total = 1,000 obs × 7 models)
  • Paired DeLong test for AUC differences
  • Wilcoxon signed-rank test on per-fold AUCs
  • Bonferroni correction for 6 comparisons

Models compared

Tabular Foundation Models (zero-config):

  • TabPFN v2 — prior-data fitted network
  • TabICL — in-context learning for tabular data
  • TabDPT — data-processing transformer

Classical baselines:

  • WoE-Logistic — production-style champion with WoE binning, IV selection, monotonicity constraints, and near-unregularized logistic regression
  • Logistic Regression — raw features, no WoE
  • XGBoost — default, then Optuna-tuned
  • LightGBM — default, then Optuna-tuned

Tuning (Pass 2)

  • Nested CV: 50 Optuna trials × 5 inner folds
  • Applied to XGB, LightGBM, plain logistic only
  • TFMs and WoE-logistic reuse Pass 1 results (no tunable hyperparameters / fixed by design)

Scope of claim

Narrow scope — discrimination only. This benchmark measures discriminatory power (AUC, Gini, KS). It does NOT address calibration quality, rating-grade stability (PSI), regulatory interpretability, or out-of-time performance. A model that ranks risk well may still produce poorly calibrated probabilities. Brier score and log-loss are reported as secondary metrics for reference, but they blend discrimination with calibration — interpreting them requires additional context.
